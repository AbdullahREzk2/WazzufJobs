# VER-08: Vercel rewrite and cookie probe (prepared for D23, **not published**)

This page checks the Vercel behaviour the proposed session design depends on:
- an external rewrite proxies `/api/*`;
- an upstream `Set-Cookie` with `__Host-` / `HttpOnly` / `Secure` / `SameSite=Strict` is stored first-party and sent back;
- multipart-sized bodies (1 to 6 MB) pass the proxy;
- which forwarded-IP headers reach the origin.

It is static HTML plus `vercel.json` only.

## Exposure verification (D23 precondition)
Confirm every item before publishing:

| Check | How to verify | Expected |
|---|---|---|
| No WazzufJobs backend involved | `vercel.json` destinations | Only `https://httpbin.org/*` |
| No secrets | Folder contents: `index.html`, `vercel.json`, `README.md`; no env vars in the Vercel project | Nothing secret present |
| No candidate data | Payloads are generated bytes (`A` repeated) and a constant probe cookie | Synthetic only |
| Separate from production | Deploy as a **new** Vercel project (e.g. `wazzuf-c0-probe`), never inside `wazzuf-jobs` | Production project untouched |
| Not indexed | `noindex` meta + `X-Robots-Tag` header; keep Vercel preview protection on | Not discoverable |
| Third-party disclosure | httpbin.org receives synthetic data plus the tester's IP/user-agent | Accept or use a self-hosted echo |

## Publish (only after D23 final approval)
```powershell
cd tools\c0\vercel-preview-probe
npx vercel deploy          # preview deployment, NOT --prod; choose "link to new project": wazzuf-c0-probe
```
Open the preview URL in Chrome, Edge, Firefox, Safari macOS and Safari iOS. Click **Run checks** and record the results table plus the header list in `docs/audit/ver-08-results.md`. Then delete the probe project: `npx vercel remove wazzuf-c0-probe`.

## Limits of this probe
- httpbin's `/delay` caps at 10 s, so the documented 30 s proxy timeout is not exercised (it is a documented provider fact).
- This tests the platform mechanics only. The real refresh endpoint is tested again in Phase 03.
